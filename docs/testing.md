# 回归检查

前端检查：

```sh
npm ci
npm run lint
npm run build
npm test
```

UI 回归需要 Python 3.12 和 Playwright。首次运行先安装浏览器：

```sh
python3 -m pip install -r scripts/requirements-ui.txt
python3 -m playwright install chromium webkit
npm run test:ui
```

Linux 可使用 `python3 -m playwright install --with-deps chromium webkit` 安装浏览器及系统依赖。

UI 运行器会启动独立端口的 Vite 服务，依次运行工作流、主题与编辑库、收件箱、过稿统计、性能、过稿数据保护、人工未读提醒、系统菜单栏未读入口和实时收件状态回归，结束后自动关闭服务。测试使用模拟 Tauri API，不读取用户数据库、不发送邮件。单独执行一项：

```sh
python3 scripts/run-ui-tests.py test-accepted-safety-ui.py
```

Rust 测试在安装了 Tauri 所需系统依赖的开发环境执行：

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked
```

`.github/workflows/checks.yml` 在分支推送和 PR 时运行上述检查：前端与 UI 使用 Ubuntu，Rust 使用 macOS。安装包发布保留独立工作流。

收件后端还覆盖：普通邮件入库和投稿统计隔离、自动回复默认已读、UIDVALIDITY 重置后的去重、跨批历史补收与新邮件优先、失败断点续传、大邮件仅收取邮件头、账号扫描互不阻塞，以及本地 IMAP 模拟服务器的 IDLE 唤醒/超时/连接复用。测试不连接真实邮箱；实际到达速度仍需在启用 IMAP 的邮箱上验证。

邮件阅读回归 `test-mail-detail-ui.py` 同时使用 Chromium 和 WebKit：完整收发件人/抄送/回复地址、HTML 表格与邮件样式、纯文本/引用切换、CID 内嵌图片、外部图片默认加载、恶意脚本/表单/嵌套页面隔离、附件保存调用、窄窗口、离线重试与切换邮件时的旧请求保护。附件保存使用模拟文件选择器，不写入用户文件。后端 MIME 样例位于 `src-tauri/src/inbox/fixtures/full-message.eml`，覆盖编码、多个正文片段、附件解码、缓存级联删除、BODY.PEEK 补取、UIDVALIDITY/Message-ID 校验和大小限制。

邮件详情性能回归 `test-mail-performance-ui.py` 覆盖视口高度邮件的布局稳定性、重复打开时详情和 HTML 处理结果复用，以及已读邮件不重复写入 IMAP 标记。

邮件竞态回归 `test-mail-races-ui.py` 验证工作台邮件入口只消费一次，延迟返回的 FLAGS 和列表快照不会撤销已完成的阅读操作。后端覆盖空收件箱后的第一封新邮件、已读→未读→已读循环的过期响应保护及历史数据库迁移；详情完成后不再等待 LOGOUT 响应。

跨模块性能回归：`test-plan-performance-ui.py` 使用 3000 份计划检查当前页渲染和任务进度更新，不读取屏幕外草稿的收件人；编辑列表模型脚本对 10000 位编辑的多次查询比较索引前后结果和耗时。编辑导入覆盖逐行错误、重复邮箱更新、收藏/启用状态保留、事务失败回滚；编辑组批量查询保持组名与成员顺序。可手动运行磁盘导入基准（独立临时数据库，WAL + FULL，不修改用户数据）：

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked benchmark_editor_batch_import -- --ignored --nocapture
```

基准耗时仅反映指定样例和本机环境，不作为 CI 性能阈值。

文件传输回归 `test-binary-ipc.mjs` 调用实际前端 API，检查文稿、编辑库、编辑组和分享图片使用原始二进制数据，中文文件名与路径正确编码，并在读取前拒绝空文件与超限文件。Rust 覆盖二进制大小及元数据校验、文稿逐块比较和已编辑副本保护。资源缓存回归覆盖并发强制刷新的请求合并，以及修改数据后旧请求无法覆盖新缓存。

模块审计回归 `test-module-audit-ui.py` 覆盖计划/设置离开保护、邮箱批量添加部分成功后的重试、编辑组串行移除、日志展开状态保留、稿件保存后任务创建失败重试复用 ID、5001 人编辑组分页，以及工作台筛选参数和趋势刷新隔离。更新流程逻辑测试覆盖启动/手动入口互斥、检查失败恢复、取消时释放资源和安装完成状态；统计缓存测试覆盖并发合并、修改失效及手动刷新。Rust 增加历史退信分类保留、跨批重分类、查询索引、授权码不返回前端、工作台先筛选后取最新、连续备份与 WAL 一致性检查。

第二轮审计新增：稿件新增/更新共享校验、模板正文回退、附件保留与替换一致性、更新已删除稿件失败；定时任务拒绝不存在的日期、非规范时间、未知发送方式和重复稿件。模块 UI 回归还覆盖设置读取失败后重试、读取失败时禁止用默认值覆盖配置，以及多个邮箱连通性测试的独立忙碌状态。所有邮件发送均由模拟 API 替代。

第三轮回归覆盖旧计划的库外收件人保留与编辑组识别、清理操作后台化、报表独立只读 WAL 快照（写入连接持锁且存在未提交事务时仍可读取已提交数据）。邮件 FLAGS 队列只保留最新排队页面；模拟 IMAP 协议覆盖短期连接复用、UIDVALIDITY 变化阻止复用、断线重连及过期/凭据变化处理，原有已读版本保护继续保留。

“设置 → 备份与空间”只展示用量并提供手动清理，不自动删除用户数据。测试在临时数据库和目录中验证按收信时间保留最新缓存、离线账号/旧命名空间缓存保护、正文摘要和已读状态不变、备份数量保留、未完成或不属于应用的文件不删除。邮件缓存清理使用版本号防止旧的网络加载回填；SQLite 文件中的空闲页供后续复用，不承诺立即缩小文件。所有 UI 清理/发送调用均为模拟 API。

边界恢复回归 `test-boundary-recovery-ui.py` 覆盖：更新重启前的当前页面未保存检查、取消重启后草稿保留、重启失败后的重试；任务插入成功但启动和列表刷新连续失败时复用同一任务；多邮箱已读状态部分成功时保留成功结果并展示具体失败邮箱，刷新成功后移除提示。更新、重启和 IMAP 都使用模拟调用。Rust 另以独立数据库验证跨批成功状态落库、全部失败返回完整错误、失败邮箱状态保持不变及重试恢复。

邮件列表与焦点回归：`test-mail-loading-and-dialog-ui.py` 在 Chromium / WebKit 中检查 QQ、163、126、Yeah 的独立服务器参数、手动服务器与端口保留、确认框 Tab / Shift+Tab 循环、背景 inert、关闭后的焦点恢复，以及原生 select 和弹窗内的浮层搜索菜单。快速打开八封未缓存邮件时只启动两个详情请求，关闭的排队项不会进入 IPC，下一空位加载当前邮件。`test-mail-request-queue.mjs` 另覆盖共享请求的独立取消、失败与不完整内容重试、缓存清理时的在途结果隔离。已开始的原生请求仍按超时结束；前后端均限制网络补取并发为两个，本地读取不占这些名额。

Rust 用 20 封各约 1 MiB 的合成正文验证列表响应低于 20 KiB、正文末尾仍可搜索、历史纯文本仍可离线按需读取；启用邮箱配置查询不依赖投递统计表。测试不连接真实邮箱、不修改用户数据库。

本地优先读取与确认队列回归 `test-local-mail-and-confirm-ui.py`：两个网络补取未结束时，第三封完整磁盘缓存直接显示，第四封旧正文先显示、再等待空位补全；旧请求完成不能覆盖当前邮件。Rust 覆盖不依赖 IMAP 连接信息的本地正文/完整缓存读取。下拉菜单的搜索框、选项和触发器按 Esc 时先关闭菜单并恢复触发器焦点，再按 Esc 才关闭父弹窗。普通模式与 StrictMode 均验证连续三个确认逐项处理，每一项都默认聚焦取消，避免下一项继承确认焦点。所有网络和操作结果均为模拟。
