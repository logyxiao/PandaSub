# 回归检查

Rust 编译警告检查：`cargo check --manifest-path src-tauri/Cargo.toml --locked --future-incompat-report` 应不再提示项目测试辅助函数的 `dead_code`，也不应提示 `imap-proto` 的宏表达式分号兼容问题。四个测试辅助函数使用 `#[cfg(test)]`；IMAP 解析器沿用 0.10.2 API，并通过 `src-tauri/vendor/imap-proto` 的本地补丁修复宏及编译器提示。来源、修改范围和许可证保存在该目录。

单独验证解析器：`cargo test --manifest-path src-tauri/vendor/imap-proto/Cargo.toml --target-dir src-tauri/target --lib`。这会运行上游解析器的原有测试，不连接邮箱；随后运行项目后端测试验证收取、正文解析和已读同步。升级依赖时应一并复核并移除不再需要的本地补丁。

编辑拉黑与替换：仅将 SMTP 550 且明确包含 `The sender is blacklisted by the recipient` 的回复识别为拉黑，按发件邮箱与编辑邮箱分别持久保存，并从历史失败日志补录。Rust 覆盖真实本地 SMTP 协议分类、旧数据库升级、单对邮箱解除、日志清空后证据保留、同平台类型筛选、已选/已投递/待确认收件人排除、连续拉黑替换、任务重启后的进度和待确认保护。自动任务保持当前发件邮箱改投，手动发送到已知拉黑地址会明确停止并提示，避免暗中改变用户指定的手动收件人。

`test-editor-blocks-ui.py` 使用模拟数据在 Chromium / WebKit 检查编辑库拉黑标记与筛选、按发件邮箱查看、单独解除一对邮箱关系的确认提示、小窗口布局，以及在其他页面收到替换或无替代编辑时的全局提示。计划发送记录显示实际改投的邮箱，重新发送的确认也使用实际收件人。测试不发送真实邮件。

邮件编码回归覆盖 GB18030（含四字节汉字）、GBK、GB2312、Big5 的主题、发件人、正文、HTML 和附件名称。旧版乱码缓存会保留离线正文并在打开时补取原邮件，正常缓存继续离线读取；缓存与列表主题、摘要同步写入，失败时整体回滚，保留已读、过稿与邮件身份。邮件详情 UI 同时检查重新解码后的标题和两种正文视图。

`test-inbox-preview-ui.py` 在 Chromium / WebKit 检查收件箱和工作台邮件跳转默认展示全部类型、无模态遮罩的右侧预览、直接切换未读邮件、当前行高亮、列表与正文独立滚动、旧请求不会覆盖新邮件、Esc 关闭后恢复列表焦点，以及 1280、960、720 像素窗口布局。托盘“查看未读人工回复”仍是显式的未读筛选入口。邮件详情、未读统计与原有收件箱回归使用同一预览区域。

## 暂停收稿分类与编辑开关

收件箱新增“暂停收稿”筛选，按已保存的主题、全文和摘录包含该词计算，不改写人工/自动/退信类型，也不自动停用编辑。历史数据无需迁移，计数及筛选在分页前完成。列表和预览显示标记；预览可显式停用/启用匹配的编辑，并显示实际收稿邮箱、作用范围和结果提示。未匹配的来信不提供开关。保存失败保持原状态，异步保存只更新所选编辑。

启用状态沿用 editors.enabled，独立更新，保留收藏和编辑资料。停用影响所有发件账号，计划匹配排除停用编辑，已有计划每次发送/重试和手动发送、重发均检查当前状态；未知的显式收件人保持原行为。停用日志分类为 editor_status，未发送不记成功，已开始的邮件无法撤回。启用不会自动补发，需重新安排未完成投递。

验证：`cargo test --manifest-path src-tauri/Cargo.toml --locked --offline --lib`（完整历史正文、分类与已读状态、账号/计划/搜索/分页组合、停用和恢复、原编辑及替代编辑发送检查）；`python3 scripts/run-ui-tests.py test-paused-inbox-ui.py test-inbox-preview-ui.py test-plan-performance-ui.py`（仅模拟 API，不发邮件、不访问用户数据库）；`npm test`、`npm run build`、`npm run lint`。


### 收件箱批量操作

邮件列表复选框与预览按钮分离，勾选不打开邮件或标记已读；支持全选/取消本页、跨页保留和清空选择，筛选条件或账号变更即清空。操作栏显示邮件数、去重后的编辑数及未匹配数量。批量暂停/启用只修改需要变化的编辑，批量删除只删除明确选中的编辑及其组成员关系，保留邮件、投递记录和已有计划收件人。删除确认列明编辑邮箱及已有计划仍可能发送的提示，停止投递应使用暂停。

两类批量命令使用单个事务，任一编辑不存在或写入失败时完整回滚，失败保留界面选择供重试。执行时禁止重复提交和单个编辑状态操作。`editor_batch_tests` 验证去重、状态恢复、资料保留、失败回滚及删除边界；`python3 scripts/run-ui-tests.py test-inbox-batch-ui.py test-paused-inbox-ui.py test-inbox-preview-ui.py` 验证跨页、筛选隔离、失败重试、删除取消、未匹配、已读状态与窄屏布局。

### 编辑平均回复时间

编辑列表新增只读统计字段 `average_reply_seconds`（无样本为 null）及 `reply_sample_count`。基于本机全部历史成功投递，使用回复与投递的 `delivery_id` 关联，按实际收稿邮箱归属编辑并合并大小写/显示名格式。每次投递仅取首个时间有效且不早于发送的人工回复，以秒为单位计算算术平均；多次发送分别计样本，重复和后续回复不重复加权，自动回复、退信、未回复、未关联、账号不符及损坏时间不计入。界面显示分钟/小时/天及有效投递数，无样本显示“暂无数据”。

不新增持久化统计列，历史数据立即适用，重新判定回复类型会重算并使编辑缓存失效；新回复事件刷新列表，未保存资料刷新延后，避免覆盖草稿。统计仅在编辑列表查询路径汇总，不在调度器发送前的编辑查询中扫描邮件历史。

验证：后端 `editor_reply_time_tests` 覆盖首次回复、重发、跨账号、重复回复、异常时间、空样本、零耗时、重新分类和调度查询隔离；`python3 scripts/run-ui-tests.py test-editor-reply-time-ui.py test-panda-ui.py` 验证时长/样本展示、事件刷新、草稿保留和窄屏布局。测试使用内存数据库或模拟 API，不访问用户邮箱、不发送邮件。

### 投稿定时开始发送

投稿编辑第三步“发送设置”提供立即/定时开始选项及电脑本地时间选择器。预约必须晚于当前时间，前端禁用无效提交并在提交时重新校验，后端继续校验格式与时效。预约调用原有 create_task/update_task 保存为 scheduled，不直接启动 SMTP；原定时任务回填时间并可修改。计划列表显示预约时间，更多菜单可取消预约；提前立即开始需确认。

调度器约每 15 秒检查一次，在认领任务时再次检查状态、发送方式与当前预约时间，防止查询后取消或推迟的预约被旧检查结果启动。取消预约与调度器使用一致的锁顺序，更新为 stopped 并广播完整任务状态。应用退出/电脑休眠时无法发送，恢复运行后到期预约会补启动；界面明确说明此条件。

验证：`cargo test --manifest-path src-tauri/Cargo.toml --locked --offline --lib` 覆盖预约输入验证、未到期/推迟任务不可认领、取消后不可认领、到期只启动一次及手动投递冲突等待；`python3 scripts/run-ui-tests.py test-scheduled-send-ui.py test-workflow-ui.py` 用模拟 API 验证选择时间、本地时间参数、预约失败重试、修改已有预约、提前发送确认和取消状态。未启动真实应用或发送邮件。

### 上个计划结束后发送与记住发送间隔

发送方式新增 after_previous，可选择更早创建的其他投稿计划，延迟 30/60/120 分钟或自定义 1–10080 分钟，默认最近创建的可选前序计划。新字段 tasks.after_task_id/delay_minutes 自动迁移；已存在计划保持原有发送方式。前序计划 completed 或 stopped 且具有 finished_at 时才按实际结束时间生成 scheduled_at；暂停、未开始或取消预约不触发，循环任务需停止才结束。生成的时间持久化，前序计划再次运行不会改写已生成的时间；调度恢复后可继续检查已到期的预约。新建计划只能引用已有计划，编辑计划只允许引用更小的任务 ID，并拒绝同一稿件互相等待。尚有未开始计时的后续预约时，删除前序计划需先取消或更改后续预约。

每次成功保存稿件（含草稿）在同一事务中记录最短/最长秒数到独立 settings.last_send_interval，失败时稿件和偏好同时回滚。普通设置保存不会覆盖该偏好。升级时从最近更新且间隔有效的稿件初始化；首次无记录时仍为 100–240 秒。新建使用上次保存值，编辑及复制已有计划保留该计划自身间隔。未保存修改不会影响下次默认值。
